A pull request is a proposed code change. Notice that the owner is involved at only two points: approving the written spec at the start, and trying the change in a preview build near the end. In between, an agent builds the change and writes its tests first, and two reviewers (Karen, our automated reviewer, and a second automated reviewer) both check it. If either reviewer finds a problem, the work goes back to the build step, never forward. Only after the owner's preview check does the change merge to the staging branch, and staging merges to main later.
